# 3D extract

Tray, conduit and cable can be turned into solids for interference checking. This is a snapshot, not a live model.

## MEDMAKE3D (everything in one go)

`MEDMAKE3D` (`Support\MED3DPath.lsp`, loaded by MEDCore) builds tray, tray fittings, conduit, conduit bodies and cable in that order with one prompt:

```
MEDMAKE3D output to [Dwg/Layer] <Dwg>:
```

| Option | What you get |
| --- | --- |
| Dwg (default) | Asks for one file name, then `-WBLOCK`s every solid this command made (tray, fittings, conduit, cable) into that single DWG and writes one `<name>.medprops.json` beside it. As with `MAKE3DTRAY` / `MAKE3DCONDUIT`, the exported solids are taken out of the current drawing. If you cancel the file dialog, the solids stay in the drawing. |
| Layer | Every solid stays in the current drawing on its own layer (`MED_3DTRAY-*`, `MED_3DCONDUIT`, `MED_3DCABLE`), and the drawing's sidecar is rebuilt if the drawing has been saved. Viewpoint is `1,1,1`; use `PLAN` to get back. |

The stages use the same code as the single commands:

1. **Tray and tray fittings:** `(med3d-tray-build)` in `MED3DTrayFunctions.lsp`, which `MAKE3DTRAY` now calls too, so the geometry is unchanged.
2. **Conduit bodies (resolve):** `(medcb-collect)` in `MED3DFittings.lsp` finds every `MED_FITTING` INSERT, works out which conduit body it is and where its hubs are. Fittings that are not conduit bodies are counted as "not modelled". See [Conduit bodies in MEDMAKE3D](#conduit-bodies-in-medmake3d).
3. **Conduit:** `(med3d-path-build-all "CONDUIT")`, the same worker `MAKE3DCONDUIT` uses. At a conduit body, the run is cut back to the hub face and gets no bend or sphere.
4. **Conduit body blocks:** `(medcb-place-all)` inserts the 3D blocks on `MED_3DCONDUIT`, or a placeholder on `MED_3DFLAG` when there is no data.
5. **Cable:** `(med3d-path-build-all "CABLE")`, the same worker `MAKE3DCABLE` uses. Cable ignores the bodies.

The tray fitting walk now skips `MED_FITTING` INSERTs, so conduit-body blocks are no longer listed as skipped tray fittings.

If one stage errors, the error goes into the summary and the next stage still runs (after a tray error the UCS is set back to World). Esc stops the whole command. OSMODE, CMDECHO and CLAYER are saved and restored, including when there is an error.

At the end it prints a summary:

```
MEDMAKE3D summary:
  Tray          : 2 solid(s)
  Tray fittings : 1 solid(s)
  Conduit       : 1 solid(s) from 1 of 2 run(s)
  Conduit bodies: 3 block(s), 1 placeholder(s), 2 fitting(s) not modelled
  Cable         : 1 solid(s) from 1 of 1 run(s)
  Flagged       : 1 (markers on MED_3DFLAG)
  Skipped       : 3
    FIT9 fitting: no solid created (not an elbow / tee / cross / reducer outline)
    2A4 conduit: no OD for this conduit type/size
    3B1 fitting: RGD|F8|TB: no 3D data for TB 3 in - placeholder on MED_3DFLAG
  Output        : C:\...\combined.dwg (+ .medprops.json)
```

- **Flagged** counts the sharp corners that got a marker on `MED_3DFLAG`, plus conduit legs at a body that no hub lines up with, plus conduit-body placeholders. KINK joints (spheres at drawn arcs) are reported per run but are not counted here.
- **Conduit bodies** counts the 3D blocks and placeholders inserted. Since r6 (MED3DPath r12) this line also counts the inline fittings (unions, seals, plugs, hubs, reducers); the label is kept. "Not modelled" counts the `MED_FITTING` inserts that have no 3D body (couplings, connectors, straps, ...); they get no solid and no message.
- **Mirrored fittings** (only printed when there are any): `Mirrored fittings: N (bad practice - re-insert without mirroring)`. Each one is also in Flagged and Skipped.
- **Skipped** lists each run or fitting that produced no solid, with the reason. A conduit-body placeholder is listed here with its handle, too.
- With `MEDDEBUG` On, the per-run MED3DPath trace follows the global flag (see `docs/debug.md`), and a one-line summary is written to the MED log.

Differences from running the single commands one after another:

- There is one prompt, one DWG and one sidecar.
- Only the solids made by this run are exported. `MAKE3DTRAY` on its own still exports every 3DSOLID in the drawing.
- There is no 3DS option.

`MED3DVER` shows whether `MEDMAKE3D` is MED3DPath's and whether the tray worker is loaded.

## MAKE3DTRAY

`MAKE3DTRAY` (`Support\MED3DTrayFunctions.lsp`, loaded with MED). Prompt:

```
Output to 3DS Layer <Dwg>:
```

Keywords: `3DS`, `Dwg`, `Layer`. Default is Dwg.

| Option | What you get |
| --- | --- |
| Layer | Solids on `_MED3DTRAY` (layer `MED_3DTRAY` in `med.spc`). Other layers off. Viewpoint isometric `1,1,1`. `PLAN` (current UCS) to get back to plan. Erase the solids before running again or they stack |
| Dwg | Export to a drawing you name |
| 3DS | 3D Studio file. 2012 preferred this over importing DWG into MAX |

Walks every `MED_TRAY` entity, then tray fittings (`MED_FITTING`), through `(med3d-tray-build)` (shared with `MEDMAKE3D`).

`ESOLID` erases **all** 3D solids in the drawing. If you use solids for anything else, do not run it.

## Conduit and cable: M3D, C3D, MAKE3DCONDUIT, MAKE3DCABLE

`Support\MED3DPath.lsp`, loaded by `MEDCore.lsp` (load is guarded; if it fails, APPLOAD `MED3DPath.lsp` to see why). One 3D solid per run.

**Loading / which version is running.** Loading prints `MED3DPath <version> loaded: M3D C3D MAKE3DCONDUIT MAKE3DCABLE MEDMAKE3D MED3DPLAN MED3DVER`; `MED3DVER` prints the version, whether each command (including `MEDMAKE3D`) is MED3DPath's or another file's, whether the tray worker is loaded, whether debug is on, and which `MED3DPath.lsp` / `MED3DCON.lsp` are first on the support path. Order: `ACAD.LSP` → `MEDCore.lsp` → … → `MED3DMisc.lsp` → `MED3DPath.lsp`. Nothing loads `MED3DCON.lsp`; the current one only defines `M3DOLD` / `MAKE3DCONDUITOLD`. If an old 2012 `MED3DCON.lsp` (its own `c:M3D` / `c:MAKE3DCONDUIT`, prompt `Output to 3DS Layer <Dwg>`) is loaded afterwards, MED3DPath takes the names back just before `M3D` / `C3D` / `MAKE3DCONDUIT` / `MAKE3DCABLE` runs (lisp reactor) and says so. LISP is per drawing: APPLOAD in one drawing does not reach another open drawing. Conduit / cable ODs are read with one quiet SELECT per command (`*MED-SQL-QUIET*`; MED-DotNet then skips its `n row(s)` line).

| Command | Does |
| --- | --- |
| `M3D` | Conduit runs you select → solids on `MED_3DCONDUIT` (`_MED3DCONDUIT`). Any polyline can be picked: each is converted by its own xdata (`MED_CONDUIT`, or `MED_CABLE` → drawn as cable, with a message); a polyline with neither is skipped with `skipped - no MED_CONDUIT / MED_CABLE xdata` |
| `C3D` | Cable runs you select (`MED_CABLE` xdata, e.g. `RUN3DCABLE` output) → solids on `MED_3DCABLE` (`_MED3DCABLE` if set, else cyan). Same selection rules as `M3D` |
| `MAKE3DCONDUIT` | Every conduit run. Prompt `[Dwg/Layer] <Dwg>`: Dwg WBLOCKs the `MED_3DCONDUIT` solids to a file you name and writes `{file}.medprops.json` beside it; Layer leaves them in the drawing and rebuilds the drawing's sidecar. Viewpoint `1,1,1`; `PLAN` to go back. 3DS is gone (no 3DSOUT in AutoCAD 2024) |
| `MAKE3DCABLE` | Same for every cable run |
| `MED3DPLAN` | Prints the corner table of one run; draws nothing |

Runs are LWPOLYLINE, 2D (heavy) POLYLINE, or 3D POLYLINE. Vertices are taken to WCS with the polyline's OCS and elevation. Meshes are skipped. A vertex closer than `*MED3D-DUP-FACTOR*` × OD (default 0.1) to the previous kept vertex is dropped (tiny jogs would otherwise leave a segment too short for any bend and force spheres at both its corners).

**Size.** Conduit OD = `med_conduit_od` (conduit code + trade size from `MEDConduitOD`, steel-pipe fallback). Cable OD = `MEDType.USER3` for the cable code. No OD → the run is skipped with a message.

**Bends.** Radius = `(med3d-bend-radius kind od override)`, 5 × OD for conduit (`*MED3D-BEND-FACTOR*`) and 7 × OD for cable (`*MED3D-CABLE-BEND-FACTOR*`). `override` is a fixed radius or `("FACTOR" . n)`; per run via `*MED3D-BEND-OVERRIDES*` = list of `(handle . override)`. Every corner between two straights gets a fillet in the plane of its two straights (works on 3D polylines). Tangent T = R·tan(θ/2) is taken from both straights. The tangents at the two ends of a straight may use the whole straight between them (no half-segment cap); end segments give their full length. Collinear vertices are merged first.

**Flags.** A corner whose T is longer than either straight, or that would overlap its neighbour, is left sharp (as few corners as possible; the smaller bend gives way) and closed with a sphere of the OD. The command line shows `MED3D FLAG: run <handle> vertex <n> bend <deg> ... needs tangent <T>, available <a>`, and a marker (3 lines, ring, text) goes on `MED_3DFLAG` (red) at the vertex. MAKE3DCONDUIT / MAKE3DCABLE clear that layer first. Drawn bulge arcs in 2D polylines are kept exactly; a non-tangent joint next to one is a KINK (sphere, message, no marker).

**Solid.** A planar run with no sharp corners: the filleted centerline is made as one temporary LWPOLYLINE, the profile circle is `entmake`d square to the start tangent, and `_.SWEEP` (mode Solid) makes the solid; the path is deleted. Non-planar 3D runs, runs with spheres, or a SWEEP that fails: straights, bends and spheres are made through ActiveX and unioned into one solid. A straight A→B is `AddExtrudedSolidAlongPath` of the profile region along a temporary LINE A→B, so direction and length come from the path; its bounding box is checked against the ideal cylinder and, if wrong or failed, it is redone with the circle + `_.EXTRUDE _Direction A B`. A bend is `AddExtrudedSolidAlongPath` along a temporary ARC entmade in the bend plane (210 = bend axis, OCS centre and angles), then, if that fails the box check, `AddRevolvedSolid` about +axis and −axis; the first result whose box holds the arc start, middle and end and is no bigger than the ideal bend is kept. Spheres come only from FLAGGED / KINK corners. OSMODE and CMDECHO are off during the command and restored on exit or error. Each solid gets `MEDProperties` via `MEDStamp3DFromBom` (CONDUIT / CABLE).

**For fittings.** `(med3d-plan-ent ent kind)` returns the plan without drawing. `("CORNERS" ...)` holds one alist per corner: `INDEX` (0-based source vertex), `VERTEX`, `ANGLE` (rad), `RADIUS`, `TANGENT`, `PTIN`, `PTOUT`, `CENTER`, `NORMAL`, `TIN`, `TOUT`, `STATUS` (`FITTED` / `FLAGGED` / `KINK`), `NEED`, `AVAIL`, `SEGIN`, `SEGOUT`. `("PIECES" ...)` is the centerline in order: `("L" A B)`, `("A" A B center axis sweep)`, `("S" point radius)`. Plans from the last command are in `*MED3D-LAST-PLANS*`.

**Old code.** `Support\MED3DCON.lsp` (not loaded) keeps the 2012 commands as `M3DOLD` and `MAKE3DCONDUITOLD`, with the EXTRUDE / OSMODE fixes. `3DJBOX` is in `MED3DMisc.lsp` (loaded).

**Debug.** `(setq *MED3D-DEBUG* T)` before `M3D` / `C3D` prints, per run: entity type, flags, vertex count, OCS normal (or `(3D)`), first WCS point; dropped near-duplicate vertices; one line per corner with its vertex, bend angle, status and reason (`FITTED - fits: tangent T <= available A`, `FLAGGED - tangent T > available A ...`, `reversal`, `KINK`); which method was used and why (`method SWEEP: plane normal ...`, `method PIECES: run is not planar` / `has sphere corners`, `SWEEP made nothing`, ...); per piece the planned start → end (length, or center and angle) and the bounding box of the solid made, plus any retry (`AlongPath box wrong ...`); and the box of the finished run. `(setq *MED3D-METHOD* "PIECES")` skips SWEEP (default `"SWEEP"`). `(setq *MED3D-DEBUG* nil)` turns it off.

**Tests.** `tests\med3dpath\test_med3dpath.py` runs the geometry in `MED3DPath.lsp` through a small AutoLISP interpreter (`python tests/med3dpath/test_med3dpath.py`). `tests\med3dpath\test_med3d_acad.py` adds a mock AutoCAD (`acadmock.py`: entity table, `trans` with the arbitrary axis algorithm, the ActiveX solid calls, SWEEP / EXTRUDE) and checks, for LWPOLYLINE (elevation, normal +Z / −Z / oblique, large coordinates, closed), 2D POLYLINE (bulges, ±Z, vertical plane) and 3D POLYLINE (sloped, vertical plane), that every solid piece or the SWEEP path and profile land on the planned centerline. `tests\autocad\MED3DPathTest.lsp` (APPLOAD, then `MED3DPATHTEST`) draws sample runs in a scratch drawing and converts them; expected results are in its header.

## Conduit bodies (rigid): MEDCBINS, MEDCBTEST, MEDCBALL

`Support\MED3DFittings.lsp`, loaded by `MEDCore.lsp` right after `MED3DPath.lsp` (guarded the same way). Size-approximate 3D blocks of Crouse-Hinds Condulet conduit bodies and inline fittings for rigid / IMC threaded conduit.

| Command | Does |
| --- | --- |
| `MEDCBINS` | Asks the type (LB LR LL T TB C X LBD BLB LBY BT BC BUB GUAL GUAT GUAX UNY EYS EYD PLGR PLGS HUB RE), the form that has it (`F7` / `F8` / `M9`, `CH`, `MOG`, `XP`, `MYR`), trade size (`1/2`, `3/4`, `1`, `1-1/4`, ...; RE also the reduce-to size), then insertion points (Enter to stop) and a rotation about Z |
| `MEDCBTEST` | Asks form and size and a base point, inserts LB LR LL T TB C X in a row along +X with a label under each |
| `MEDCBALL` | Gallery: every type of every form at one trade size, one row per form, labelled; a type with no row for that size gets its placeholder |
| `MEDCBDATA` | Re-reads the data and lists the sizes available per form / shape |
| `MEDCBVER` | Version, row count, CSV path |

**Data.** `MEDConduitBody` (see `docs/database.md`), else `Data\seed\conduit_body_dims.csv` read directly. Values are the Eaton Crouse-Hinds catalog dimensions a-e (source id + page per row, publications in `Data\seed\conduit_body_sources.csv`). Coverage: Form 7 C 1/2-3, LB/LL/LR/T 1/2-4, TB 1/2-2; Form 8 C/LL/LR/T 1/2-3, LB 1/2-4, TB 1/2-2; Mark 9 C/LB/LL/LR/T 1/2-4, TB 1/2-2; X for all three forms (r6). Phase 2 (r6) adds CH LBD / LBY / UNY / EYS / EYD / HUB, Mogul BLB / BC / BT / BUB, GUA L / T / X (form `XP`) and the Myers ST hub from the published tables, and PLGR / PLGS / RE as rows marked approx (derived from the Wheatland coupling `WH CPL` and the ANSI C80.1 OD; the plug catalog page has no dimensions). The per-fitting sources are in [3d-fitting-matrix.md](3d-fitting-matrix.md#phase-2-bodies-done-in-r6). After editing the table, run `MEDCBDATA` (or `(setq *MEDCB-DATA* nil)`) to reload.

**Blocks.** `MED_CB_RGD_<form>_<shape>_<size>`, size = trade size with two decimals and `-` for the point: `MED_CB_RGD_F7_LB_1-00`, `MED_CB_RGD_F8_T_1-25`, `MED_CB_RGD_F7_C_0-50`. Reducer: `MED_CB_RGD_CH_RE_1-00X0-75` (large X small). A block is made the first time it is needed and never redefined (delete / purge it to get a fresh one). No data for that form / shape / size → a plain box in `<name>_PH`. Inserts go on `MED_3DCONDUIT` (`MED_3DFLAG` for placeholders). **Block rule (Clint, r6):** every entity inside a block - body, cover, placeholder box - is on layer 0 with colour, linetype and lineweight ByLayer; the insert carries the layer (and so the colour). Blocks made by r5 or earlier (gray colour-8 cover, red placeholder) carry an older tag and are renamed `<name>_PRE_R6` the first time they are needed, then rebuilt; run `PURGE` (Blocks) afterwards to remove the `_PRE_R6` definitions once nothing references them. Drawing units are inches.

**Block axes.** Insertion point = where the conduit centerlines entering the body cross (C: body centre on the axis). Cover faces +Z. Centerlines are in Z = 0 (mid-depth). Hub directions (outward, toward the conduit):

| Shape | Hubs |
| --- | --- |
| C | RUN +X, RUN2 −X |
| LB | RUN +X, BACK −Z |
| LL | RUN +X, BRANCH −Y |
| LR | RUN +X, BRANCH +Y |
| T | RUN +X, RUN2 −X, BRANCH +Y |
| TB | RUN +X, RUN2 −X, BACK −Z |
| X, GUAX | RUN +X, RUN2 −X, BRANCH +Y, BRANCH2 −Y |
| GUAL | RUN +X, BRANCH +Y |
| GUAT, BT | as T |
| LBD, BLB, LBY | as LB (LBY: round cover on the 45° corner toward −X +Z) |
| BC | as C |
| BUB | RUN +X, RUN2 −X at the hub faces (the hubs slope 45° down to them) |
| UNY, EYS, EYD | RUN +X, RUN2 −X (EYS: bulge and pour hub +Z, leaning boss toward +X; EYD r9: the same mirrored to −Z, ECD drain straight down −Z) |
| PLGR, PLGS | RUN +X (plug at −X) |
| HUB | RUN +X, wall face at X = 0 |
| RE | RUN +X (small size), RUN2 −X (large size) |

Looking down on the cover with RUN pointing east, LL opens south and LR north (trade rule: cover toward you, end hub down, side opening left = LL). `(medcb-hubs form shape size)` returns `((name face-point direction) ...)` in block coordinates (face point = where the conduit enters) for placement code; `(medcb-ensure-block form shape size)` returns `(name status)`; `(medcb-insert form shape size wcs-point rotation)` inserts one.

**Model.** Body = slot (rounded ends) W × H, hubs = cylinders, cover = thin slot on top. A, B and C of the block equal the catalog values. Not published, so derived: body section (the catalog gives only overall sizes; square section assumed), hub OD (≤ body section, ≥ 1.15 × rigid OD when `med_conduit_od` is available), hub length, and the side / back hub position (centre of the round end for LB / LL / LR, middle for T / TB). The rules are in the file header; the phase 2 builders (`medcb-geom-lby` … `medcb-geom-re`) say which of their parts are derived (LBY and BUB internals, GUA cover and hub OD, hub ODs in general).

**EYS (r7).** Reworked after Clint's reference model of the real fitting: the conduit runs straight through a bored tube with plain hub rings at the ends; the body swells out on the +Z side into an eccentric bulge `b` wide; on top a large, short pour hub with a recessed plug and a square drive; beside it (toward +X) a smaller boss leaning 40° with its own recessed square-drive plug and slanted face; the EYD adds a drain leaning 45° down toward +X (boss, hex nut, cartridge). Published: `a` overall length, `b` body width and `D` = turning radius (axis to the farthest face) - the pour-hub face for 1-1/4" and up, the leaning boss rim for 1/2" - 1" (the catalog's angled body). All other proportions are **approx** (estimated from the catalog drawings / photos and Clint's reference). The builder uses two r7 primitives: cuts (plug seats, square drives, bore, subtracted after the unions) and regular prisms (square drive, hex nut). Only EYS / EYD blocks get the r7 tag; an older EYS / EYD block in a drawing is renamed `<name>_PRE_R7` and rebuilt the first time it is needed (PURGE it afterwards); all other r6 blocks are left alone. No bores, threads, cover screws or gaskets.

**Turning-radius limit (r9, Clint).** On every EYS and EYD, nothing of the body or its plugs reaches past the catalog turning radius `D` (conduit axis to the farthest point), at every size - the rim corners of the pour hub and the leaning boss count, not only their face centres. 1-1/4" and up: the pour hub's rim touches `D` (its face is at √(D² − r²)), the boss rim stays 0.03 `b` inside; 1/2" - 1": the boss rim touches `D`, the pour hub stays short. The test checks the farthest point of every part of every EYS / EYD row: ≤ `D` and ≥ `D` − 0.031 `b`.

**EYD (r9).** Exactly the EYS body (same bulge, pour hub, leaning boss, same limit against the EYD's own `D`), mirrored so the large opening is the lower one (−Z): Clint's 2D side view (proportion reference only, `CLINT-EYD-PROFILE`) shows the large plug along the bottom and the angled boss on the lower corner toward +X. The plug in that opening is a special plug that takes an ECD drain: a 1/2" Crouse-Hinds ECD11 threaded into it, pointing straight down - hex 0.88" across flats × 0.28", body dia 0.62", 1.06" below the plug (published: 1.56" long, 0.88", `EATON-ECD11`; the hex / body split is **approx**). The ECD is the only part that goes past `D`. The r8 cylinder body, lower chamber and pad are gone.

**GUAL / GUAT / GUAX (r9).** Tuned to Clint's reference DWGs (`C:\Users\moore\Dropbox\Development\3DFittings`, GUA?4A 4B 6C 7D 9E 9F = our 1/2" - 2" catalog rows, measured solid by solid; source `CLINT-GUA-DWG`); his files are not imported. Body dia = catalog `a` (as his); hub face at `a`/2 + HubLen (his faces; the catalog `c` is 1/16" - 3/8" off his models and no longer sets the face); hub OD per trade size as his (1.25 / 1.5 / 1.75 / 2.1875 / 2.5625 / 3.0), bored to the conduit OD; bottom = hub OD / 2 below the hub axis (his; = catalog `d` except 1-1/2": 1.281 vs 1.219); height per body: body + full-diameter cover disc (0.125", 0.334" on the 5.75" body) to 1.9375 / 2.4375 / 2.8125 / 4.394" above the bottom, plus two wrench lugs (0.375", 0.569" on the 5.75" body). A GUA size / body not in those tables keeps the r6 catalog proportions.

**Revisions r9.** EYS, EYD, GUAL, GUAT and GUAX blocks get the tag `MEDCB geom r9`; an older one in a drawing (r6, r7, r8) is renamed `<name>_PRE_R9` and rebuilt the first time it is needed (PURGE the `_PRE_R9` blocks afterwards). All other blocks stay r6.

### Conduit bodies in MEDMAKE3D

Every 2D symbol × code × leg case, with the expected and current result, is in [3d-fitting-matrix.md](3d-fitting-matrix.md). `MEDCBGRID` (`tests\autocad\MEDCBGrid.lsp`) draws them all in a test drawing.

`MEDMAKE3D` turns the 2D conduit-body fittings placed from the MED fitting menu (`MED_FITTING` xdata on a block INSERT) into these 3D blocks. `M3D` / `MAKE3DCONDUIT` on their own do not; they work as before.

**Which body.** The fitting code is looked up in `MEDType` (ITEMTYPE `FITTING`):

1. `ITEMKEY2` = body key `material|form|shape`, e.g. `RGD|F7|LB`, `RGD|M9|TB`, `RGD|F8|C`, `RGD|XP|GUAT`. MED-DotNet fills blank ITEMKEY2 on the stock rows (codes 11-16, 18, 30-41, 50-53, 61, 64, 72, 80-82, 94, 100, 101, 103, 120, 121, 141-143) from `Data\seed\fitting_body_keys.csv` at load, matched on the description, and never overwrites a value. You can type your own key in MEDTYPE.
2. If ITEMKEY2 is blank (for example the new DLL is not installed yet), the key is read from the description: only descriptions containing `condulet` count; form from `Form 7` / `Form 8` / `Mark 9` (`Mogul` → `MOG`, `Explosion Proof` → `XP`, LBD / LBY with no form → `CH`); shape = the quoted word (`"LB"`), else the word before `condulet`.
3. Else the seed CSV row for the same code, but only when its description equals the database description (unions, seals, plugs, hubs, reducer). No database: the seed CSV is used by code.

Size = the fitting's trade size (`#ITEMSIZE`). Reducer: the reduce-to size is the fitting's alt size (`#ITEM_ALT`); if it is missing, one trade size down, with a note. Anything else (couplings, connectors, straps, ...) is "not modelled".

**Placement.** Insertion point = the 2D block insertion point (WCS). Z = the conduit elevation at that point when a conduit run passes through or ends there (it wins over the block Z). Rotation = the 2D block rotation about Z, plus the offset the menu block implies (`1tee*` T -90°), plus the tilt the symbol implies (below). Then, with `*MEDCB-SNAP*` T (default), MEDMAKE3D tries the four quarter turns (and, for the LB family / TB / LL / LR, the other tilts) and keeps the one whose hubs best match the conduit legs at that point. On a tie the drawn rotation is kept. Set `(setq *MEDCB-SNAP* nil)` to use the drawn rotation only.

**Tee up / down.** Code 11-13 (T) on the tee-down / tee-up menu blocks (`1teed`, `2teed`, `1teeu`, `1teeuo`) is modelled as a TB, with the back hub down (tee down) or up (tee up, block turned over). A TB code on a flat tee (`1tee`) is tilted so its back hub takes the branch, opening opposite it. TA (code 17) is modelled as a T.

**LB family.**
- LB down (`1lbd`): back hub down, cover up.
- LB up (`1lbu`, `1lbuo`): turned over (180° about its run), so the back hub points up and the cover faces down.
- LB, LBD, LBY and Mogul BLB on a flat-turn symbol (`1lbl`, `1lbr`, `1lbdl`, `1lbdr`, `1lby`): the body lies on its side along the symbol's long leg (block +X, the conduit picked), the back hub toward the short leg (+Y on `1lbl`, -Y on `1lbr`) and the cover sideways, away from it - even when only one leg is drawn. With snap on, a better fit on the legs wins. Both legs are cut back to the hub faces, no flag. The tilt is applied with `Rotate3D` about the block's rotated X axis (`*MED3D-DEBUG*`: `tilted 90 deg about X`). LBD / LBY / BLB have real bodies since r6.

**LL / LR.** With the cover up and the RUN (end) hub at +X, the LL's side hub is at +Y and the LR's at -Y (fixed in MED3DFittings r5; they were swapped). The body lies along the symbol's long leg; if the code's side hub doesn't point at the short leg with the cover up, the body is turned over (cover down): LR on `1lbl`, LL on `1lbr`. LL / LR blocks made before r5 are renamed `<name>_PRE_R5` and rebuilt the first time MEDMAKE3D needs them.

**Vertical conduit.** The up / down conduit placed with a fitting is stored on the fitting insert (`MED_CONDUIT` distance, `VERT_DATA` direction ±1). MEDMAKE3D builds it as a cylinder (same OD and layer as the conduit) from the face of the hub pointing that way to insertion Z ± the distance, and counts it in the summary. No hub pointing that way → built from the insertion point and flagged.

**Notes (not flags).** MEDMAKE3D prints `MED3D note: fitting <handle> (<key>): ...` for information such as a TA modelled as a T.

**Conduit at a body.** A run vertex or run end within the fitting's break distance (`Support\medblck.dat` × the insert scale) + `*MED3D-FIT-TOL*` (0.25") in XY (Z within the larger of 0.25" and the OD) of a body insertion point:
- gets no bend and no sphere. The corner is sharp and not flagged (`FITTING` in `MED3DPLAN` / debug);
- each leg is trimmed back (or extended, when the menu broke it farther back) to the face of the hub that lines up with it within `*MED3D-FIT-ANG*` (30°). No hub within 30° → the leg is left at the insertion point and flagged (message + marker on `MED_3DFLAG`);
- the bend next to the body gets only the length left after the cut.
A run that passes straight through a C or T body (no vertex there) stays one continuous solid.

**Phase 2 bodies on plan symbols (r6).** X, GUAX, BUB, seals, union: face up on the symbol. GUAT on `1guat`: -90° like `1tee` (branch = symbol +X). GUA side views (`1gualsid`, `1guatsid`): tilted -90° about X - branch down, cover toward +Y. Hub: wall face at the insertion point. Plugs: the coupling on the conduit end. Union / hub / reducer: the menu breaks the conduit back farther than the body; MED3DPath r12 accepts a leg end beyond the usual tolerance only when it lies on that hub's plan axis, within the hub's break radius, and extends it to the face.

**No data.** Body keys without 3D data (a form or size missing from the table, a type that is not modelled, no trade size) get a placeholder box on `MED_3DFLAG`, a flag marker, and a `Skipped` line with the handle and reason.

**Debug.** With `*MED3D-DEBUG*` on, each body prints its code, key and where the key came from (ITEMKEY2 / DESC / CSV), shape, size, 2D block, rotation, number of conduit legs and quarter turns.

**Mirrored symbols.** A mirrored `MED_FITTING` conduit body (X scale × Y scale × extrusion Z < 0, e.g. made with MIRROR) is not accommodated: no 3D body, the adjacent conduit is left as drawn (no trim, no leg flag), one marker `MIRRORED FITTING - re-insert, do not mirror` on `MED_3DFLAG`, a `Skipped` line with the handle and reason, and the summary line `Mirrored fittings: N (bad practice - re-insert without mirroring)`. Re-insert the symbol without mirroring (e.g. `1lbr` instead of a mirrored `1lbl`).

**Limits (this round).** Rotation about Z plus the tilts above. The reducing coupling (REC), EYS elbows and EZS / EZD are not modelled; plugs and reducers are approx; BUB hubs are treated as horizontal by the planner; mirrored 2D blocks are flagged, not built; arcs next to a body are not trimmed; a TB for a tee up has its cover facing down.

**Tests.** `python tests/med3dpath/test_med3dfittings.py` runs the LISP through the same mini interpreter with a block / solid mock: naming, size parsing, the CSV reader on the real seed file, the geometry of every row (hub faces and directions, origin on the branch / back axis, overall A / B / C), the solids made for a block, no redefinition, placeholder, DB rows over CSV rows, `MEDCBTEST` spacing, and that every block entity is on layer 0 and ByLayer (and every insert ByLayer on its layer). `python tests/med3dpath/test_med3dphase2.py` builds every phase 2 row and checks its hubs and overall dimensions against the published letters, the RE / GUA / hub placement, the on-axis leg guard and `MEDCBALL`.

Internal test commands (`TRAYTEST`, `TRAYFITTEST`, `QVTEST`, `MYTEST`, …) are not user commands.
