# AutoLISP developer reference

Every `defun` in the MED LISP, grouped by source file: signature, arguments, return value, purpose and side effects (globals, xdata, layers, DB access). One page per file under [lisp/](lisp/). Users want [command-reference.md](command-reference.md) instead. The 3D modules are summarised in [3d-guide.md](3d-guide.md).

Generated from the code on `feature/3dpath`; purposes come from the comments in the code where there are any, otherwise from reading the function. Items marked **TODO: confirm with Clint** are not settled by the code. File and line for every entry are also in [doc-audit.csv](doc-audit.csv).

## Load order

`ACAD.LSP` loads `CSharpAdd.lsp` (MED-DotNet), `QKEY.lsp`, then `MEDCore.lsp`. MEDCore loads, in order: `MEDVariables`, `medtray`, `medcon`, `medwire`, `medsetup`, `MEDFunctions`, `MEDTextStyles`, `MEDDatabase`, `MEDCommands`, `medcable`, `MEDCableTray`, `MEDBuildXData`, `MEDDim`, `MED3DTrayFunctions`, `medchg`, `meddetl`, `medinser`, `medtext`, `medtag`, `medutil`, `MED3DMisc`, then (guarded, a load error does not stop MEDCore) `MED3DPath` and `MED3DFittings`, then `med.spc`. After that MEDCore defines the stub `MED_cur_set`, registers the xdata apps and sets core globals. `med.mnl` is loaded by AutoCAD with the `med` menu group. When a name is defined twice, the definition loaded last wins; each duplicate says which one wins.

Not loaded: `MED3DCON.lsp` (2012 3D conduit), `MED2026-ProfileSetup.lsp` (APPLOAD once for `MED2026SETUP`), `tests\autocad\*.lsp`.

## Conventions

- **Xdata apps** (registered in MEDCore): `MED_CONDUIT`, `MED_CABLE`, `MED_TRAY`, `MED_FITTING`, `MED_EQUIP`, `MED_ELEC`, `MED_RELATE`, `MED_ATTRIB`, `MED_DOUBLE`, `VERT_DATA` (vertical direction / distance), `MEDProperties` (3D model ID only, not BOM). Globals `_CONDUIT`, `_CABLE`, `_TRAY`, `_FITTING`, `_EQUIP`, ... hold the app names. Records are built by `bld_conduit` / `bld_cable` / `bld_tray` / `bld_fitting` / `bld_equip` (`MEDBuildXData.lsp`), written by `xdatadd`, read by `xdataget` / `xd_apps`, removed by `xdstrip` (`MEDFunctions.lsp`).

- **Globals**: MED settings are `_UPPERCASE` symbols from `MEDVariables.lsp`, overridden by `med.spc`, changed by `MEDSETTINGS` (through `MED-GetSym` / `MED-SetSym`). The 3D modules use `*EARMUFF*` globals (`*MED3D-DEBUG*`, `*MED3D-BEND-FACTOR*`, `*MEDCB-SNAP*`, ...); see [3d.md](3d.md).

- **Layers**: layer specs are lists `(name colour linetype [lineweight])` in globals such as `_MCON`, `_MEDTRAY`, `_MEDTEXT`, `_MED3DFLAG`; `smlayer` / `medsmlayer` make one current (creating it). The 3D output layers are `MED_3DTRAY*`, `MED_3DCONDUIT`, `MED_3DCABLE`, `MED_3DFLAG`.

- **Database**: all SQL goes through `ProcessSQLStatementNET` (MED-DotNet), wrapped by `MEDProcessSQLStatement` (`MEDDatabase.lsp`). Rows come back as lists, header row first. `*MED-SQL-QUIET*` suppresses the row-count message. See [database.md](database.md).

- **Command wrapper**: most commands call `(med_cur_set "c:NAME")` at the start and `(med_ret_ok)` at the end. Note the stub `MED_cur_set` MEDCore defines after loading MEDFunctions.lsp replaces the full version, so the MED error handler it would install is not installed (TODO: confirm with Clint).
